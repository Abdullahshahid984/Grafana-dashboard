## 1. The timeline: who changed the policy and when
```kusto
AzureActivity
| where TimeGenerated between (datetime(2026-11-05) .. datetime(2026-11-09))
| where ResourceProviderValue =~ "MICROSOFT.APIMANAGEMENT"
| where _ResourceId has "apim-ads-cus-entbusops-prd-001"
| where OperationNameValue matches regex @"(?i)(POLICIES|POLICYFRAGMENTS|NAMEDVALUES)/(WRITE|DELETE)$"
| project TimeGenerated, OperationNameValue, Caller, ActivityStatusValue
| order by TimeGenerated asc
```
**Result you got (13 rows):**

| Time (UTC) | What | Who |
|---|---|---|
| 6 Nov 04:21 to 04:22 | Named value written (4 log rows for one write) | First account |
| 04:23 | Policy written | Same account |
| 04:24 | Policy written again | Same account |
| 17:33 | Policy written | A different account |

**How it works:** Azure records every write to APIM as an Activity Log event. Each write appears as several rows (Start, Accept or Succeeded, Success), which is why 4 writes make 13 rows. The regex keeps only writes and deletes to policies, policy fragments and named values, so the thousands of "read" events don't drown them. The first writes added Traceable, and the last one removed it.

## 2. Calls from APIM to the agent: did they work?
```kusto
AppDependencies
| where TimeGenerated between (datetime(2026-11-06T04:20:00Z) .. datetime(2026-11-06T17:40:00Z))
| where Target has "10.37.136.100" or Data has "10.37.136.100"
| summarize calls=count(), failed=countif(Success == false), p95_ms=percentile(DurationMs, 95), max_ms=max(DurationMs)
            by bin(TimeGenerated, 1h), ResultCode
| order by TimeGenerated asc
```
**Result you got (14 hourly rows, 04:00 to 17:00 UTC):**

| Hour | Calls | Failed |
|---|---|---|
| 04:00 to 10:00 | 1.3 to 2.6 million per hour | 0 |
| 11:00 to 12:00 | 3.4 and 4.3 million | 0 |
| 13:00 to 16:00 | 6.1, 6.5, 6.5 and 6.4 million | 0 |
| 17:00 | 3.5 million | 0 |

That is about **50 million calls with no failures**. Duration shows 0 ms in every row, except one 301-second outlier in the 16:00 hour.

**How it works:** APIM's Application Insights logger records each outbound call from a policy as a "dependency" record. We filter for the agent's address, count calls per hour, and count the ones marked unsuccessful. Zero failures means the calls reached the agent and got an answer, so the path (including any firewall) was open. Duration isn't filled in for these records, so use query 3 for timing.

## 3. Friday with Traceable against Thursday without, by payload size
```kusto
ApiManagementGatewayLogs
| where TimeGenerated between (datetime(2026-11-06T05:00:00Z) .. datetime(2026-11-06T17:30:00Z))
     or TimeGenerated between (datetime(2026-11-05T05:00:00Z) .. datetime(2026-11-05T17:30:00Z))
| extend period = iff(TimeGenerated >= datetime(2026-11-06), "Fri with Traceable", "Thu without")
| extend size_bucket = case(RequestSize < 10000, "1 under 10KB", RequestSize < 131072, "2 10KB-128KB", RequestSize < 1000000, "3 128KB-1MB", "4 over 1MB")
| summarize requests=count(), p50_ms=percentile(TotalTime-BackendTime,50), p95_ms=percentile(TotalTime-BackendTime,95),
            p99_ms=percentile(TotalTime-BackendTime,99), over_8s=countif((TotalTime-BackendTime)>8000)
            by size_bucket, period
| order by size_bucket asc, period asc
```
**Result you got (time inside APIM, in ms):**

| Payload | Friday (Traceable on): requests, p50, p95, p99 | Thursday (off): requests, p50, p95, p99 |
|---|---|---|
| Under 10 KB | 133.0M, 1, **27**, 59 | 118.9M, 1, **11**, 39 |
| 10 to 128 KB | 1.51M, 2, 8, 104 | 1.52M, 2, 5, 94 |
| Over 1 MB | 494K, 1, 7, **408** | 483K, 1, 3, **6** |
| 128 KB to 1 MB | only 137 requests | 373 requests |

**How it works:** `TotalTime - BackendTime` is the time spent inside APIM itself (policies and overhead), leaving out the backend. Comparing the **same hours on two days** controls for the daily traffic pattern. The result: about +16 ms at p95 for ordinary requests, and a much slower tail for the largest requests, which matches the policy reading whole bodies into memory.

## 4. Where the Friday 5xx errors came from
```kusto
ApiManagementGatewayLogs
| where TimeGenerated between (datetime(2026-11-06T15:00:00Z) .. datetime(2026-11-06T17:30:00Z))
| where ResponseCode >= 500
| summarize errors=count() by ResponseCode, BackendResponseCode, LastErrorSource, LastErrorReason, ApiId
| top 20 by errors desc
```
**Result you got (top rows):**

| API | Response / backend code | Error source in APIM | Errors |
|---|---|---|---|
| StatementsAPI | 500 / 500 | none | 8,737 |
| AccountMaintenanceAPI | 500 / 500 | none | 3,990 |
| financialadjustments | 500 / 500 | none | 3,572 |
| StatementsAPI | 503 / 503 | none | 1,422 |
| digitalapifraudnetproxy | 500 | forward-request, BackendConnectionFailure | 794 |
| fiserv-document-api | 500 / 500 | set-variable, ExpressionValueEvaluationFailure | 762 |

**How it works:** if `BackendResponseCode` equals `ResponseCode` and `LastErrorSource` is empty, the backend produced the error and APIM only passed it on. If `LastErrorSource` names a policy step, APIM itself raised it. About 92% of the top 20 were the first kind, mostly Statements, so the spike was in the backends.

## 5. The vendor policy: timeout, fail-open setting and address fallback
```powershell
New-Item -ItemType Directory -Force "$env:TEMP\traceable-policy" | Out-Null

```
**Result you got (key lines):**
```
policy.xml:30:  var fallbackEndPoint = "http://localhost:5442";
policy.xml:44:  <send-request mode="new" response-variable-name="traceable-response" timeout="10" ignore-error="true">
policy.xml:46:  ... "/ext_cap/v1/evaluate_blocking"
```
**How it works:** the download saves the file to a temporary folder, and `Select-String` prints the matching lines with their line numbers. Line 44 shows a **10-second timeout** and **fail open** (`ignore-error="true"`), and line 30 shows the silent fallback to `localhost:5442` when the named value isn't in the right format. Don't open this file in a browser: it contains code that browsers reject, so use PowerShell or Notepad.

## 6. Errors raised inside APIM, with and without Traceable
```kusto
ApiManagementGatewayLogs
| where TimeGenerated between (datetime(2026-11-06T05:00:00Z) .. datetime(2026-11-06T17:30:00Z))
     or TimeGenerated between (datetime(2026-11-05T05:00:00Z) .. datetime(2026-11-05T17:30:00Z))
| extend period = iff(TimeGenerated >= datetime(2026-11-06), "Fri with Traceable", "Thu without")
| where isnotempty(LastErrorSource)
| summarize errors=count() by period, LastErrorSource, LastErrorReason
| order by errors desc
```
**Result you got (main differences):** `forward-request / ClientConnectionFailure` was **25,433 on Friday against 1,929 on Thursday** (callers hanging up, 13 times more), `transfer-response / ClientConnectionFailure` 911 against 77, and `forward-request / Timeout` 357 against 70. Everything else was similar on both days. **How it works:** it counts only the errors that APIM itself recorded, grouped by which policy step failed and why, so a new error type that appears only on Friday would show the fingerprint of the change.

## 7. The named value and the agent's owner (PowerShell)
```powershell
az apim nv list -g $rg --service-name $apim --query "[?contains(name,'traceable') || contains(name,'tpa')].{name:name,secret:secret,value:value}" -o table

$body = @{ query = "Resources | where properties contains '10.37.136.100' | project name, type, resourceGroup, subscriptionId" } | ConvertTo-Json -Compress
[System.IO.File]::WriteAllText("$env:TEMP\arg.json", $body)
az rest --method post --url "https://management.azure.com/providers/Microsoft.ResourceGraph/resources?api-version=2021-03-01" --body "@$env:TEMP\arg.json" --query "data" -o json
```
**Result you got:** the named value `traceable-endpoint` (not secret) with the agent address and port 5442 in the accepted format, and the address belonging to the load balancer **`ilb-bfh-traceable-cus-prd-01`** in the information security team's resource group.

**How it works:** the first command lists the named values (this CLI version doesn't show them in other places). The second asks Azure Resource Graph, through a REST call, which resource in any subscription you can read contains that IP, which avoids installing an extension. It found a load balancer, so the agent is real and owned by another team. Blur the subscription ID before sharing.
