# End of Year Review 2026: Platform Engineering (AKS / IHUB)

## Overview

This year I owned AKS platform infrastructure for IHUB across dev, POC, SIT, UAT, perf and prod. My focus was on making the platform more recoverable and reliable. I built and rolled out AKS backup and restore, kept the shared Terraform code healthy, took on APIM support after a knowledge transfer (KT) session, and helped resolve cross-team incidents.

## Key Achievements

**AKS Backup and Restore**
- Built the AKS backup infrastructure in Terraform on Azure Data Protection and validated full restores. Restore testing needed fixes for identity, autoscaling, secrets and image-pull issues.
- Automated federated credential creation for restore clusters in the onboarding pipeline. Phase 1 restored 71 namespaces from DEV to POC-02, and Phase 2 delivered a dedicated DEV-RST cluster with all workloads onboarded.
- Rolled backup out to SIT, verified the first backup job, and fixed a policy ordering problem so the pipeline now succeeds in one run.
- Rebuilt the backup and restore presentation and a presenter script, presented it to the team and recorded it for those who couldn't attend.

**APIM Support and Knowledge Transfer**
- Took part in a KT session on APIM and took on APIM pipelines, access and change requests.
- Prepared, applied and verified the Prod APIM header logging change (RITM0553840 / SCTASK0729498).
- Handled APIM access and product provisioning requests through ServiceNow.
- Diagnosed the Dev APIM Terraform pipeline failure from the plan log and explained the cause and next step.
- Investigated the PERF APIM deployment failures (Release-1132) using the release logs and ARM deployment history. The causes were API path clashes and missing named values. I gave the requesting team a clear fix: resolve the path conflicts or use a version set, add the named values, clear or import the failed deployments, then re-run.
- Flagged unplanned changes from the partial apply (product approvals and a rate-limit policy) and advised reading the plan before the next run, because the pipeline applies automatically.
- Explained that PERF is in a different Entra tenant from Dev, which is why a requester could not see PERF resources, and told them the access they needed.
- Gave guidance on a partner API URL issue, listing the details needed to investigate it.

**Platform Code Health**
- Fixed recurring Terraform drift on POC-01 and POC-02 in the shared AKS module, so every environment is protected.
- Upgraded Azure Managed Grafana to v12 before the deprecation, and added support for custom domains through the shared Istio gateway.

**Incident Support**
- Completed the cluster side of a failed Istio upgrade on perf.
- Found the real root cause of Harness failures across all clusters (a Helm chart ConfigMap and a stale build cache), which avoided an unnecessary RBAC change.
- Diagnosed 500 errors and CrashLoopBackOff on several APIs, and resolved a production KANA API key incident.

## What I Learned

- Identity, RBAC and autoscaling are tightly linked on this platform, so I now test shared module changes against other environments before raising a PR.
- Terraform orders resources by references, so I check for plain-string dependencies in reviews.
- I verify with evidence before replying, and I keep confirmed facts separate from assumptions.
- Taking on a new area like APIM shows how much depends on a clear handover, so I document what I learn as I go.

## Goals for Next Year

- Finish the agreed backup items: an alert on the -rst cluster, and a dedicated snapshot resource group covering PinDrop and future persistent volumes.
- Roll backup out to UAT, perf and prod, and run a full DR test.
- Turn backup and restore into a documented runbook so it doesn't depend on one person.
- Keep reducing manual changes outside Terraform.
