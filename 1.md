I have completed the troubleshooting for the connection reset issue causing the CrashLoopBackOff in the api-statements-v1 namespace. The investigation showed that the application is currently configured to connect to acs16x014.database.windows.net, which is an isolated SIT database server. Because our DEV AKS cluster has no Private Endpoint access to the SIT network layer, the server firewall is forcefully dropping the traffic. I confirmed this environment mismatch with the DBA team, and they verified that the correct server host for the DEV environment is acs26x008.database.windows.net (Database Name: sdb-ads-eus2-entbusops-dev-ihub-customer-001). Please update your deployment pipeline parameters to pull from the DEV configuration profiles instead of SIT, then execute a manual rollout restart command to cycle the pods so they can connect cleanly to the new database endpoint.
