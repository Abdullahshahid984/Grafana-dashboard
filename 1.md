Find the Helm release name, chart and version:

```bash
helm list -n api-profile-v1
```

Back up the current values before changing anything:

```bash
helm get values <release> -n api-profile-v1 -o yaml > profile-values-backup.yaml
```

See which key holds the env variables:

```bash
helm get values <release> -n api-profile-v1 --all
```

Change the variable, keeping the same chart version and every other value:

```bash
helm upgrade <release> <chart> -n api-profile-v1 --version <current-chart-version> --reuse-values --set env.<VAR_NAME>=<value>
```

Verify the rollout and the new value:

```bash
kubectl rollout status deployment/<deployment> -n api-profile-v1
```

```bash
kubectl exec -n api-profile-v1 <pod> -- printenv <VAR_NAME>
```

Roll back if something goes wrong:

```bash
helm rollback <release> <previous-revision> -n api-profile-v1
```

Fill in `<release>`, `<chart>`, `<current-chart-version>` and `<VAR_NAME>` from the output of the `helm list` and `helm get values` commands. The `--set env.<VAR_NAME>` key is a guess, so use the key you actually see in the `--all` output, or the upgrade may add a new value and not change the existing one.

The upgrade restarts the pods in a rolling update. A later pipeline deploy overwrites a manual upgrade, so ask the requester if the change is only for the test.
