I don't have a formal doc, but this is what we can fill in for an APIM release: the release branch and the APIs or products changing, the configuration items (the APIM instances, the repos and the release pipeline), the impacted services, risk and impact, the deployment steps in order of environment, a test plan, a rollback plan, the release window and the approvers. I'll share the CR once it's raised so you can use it as an example.

## What to put in each CR field

| Field | Content |
|---|---|
| **Short description** | APIM release `2026-NOV-REL1`, 16 Nov 2026: `<one line on what is changing>` |
| **Justification** | Releases the approved APIM changes from `develop` to production: `<new APIs or operations, policy changes, named values, product or subscription changes>`. Link the Jira tickets. |
| **Configuration items** | The APIM instances `<External and Internal, and CUS or EUS2 as applicable>`. The repos APIM.External and APIM.InHub, branch `release/2026-NOV-REL1`. The release pipeline. |
| **Impacted services** | The APIs and products changed in this release `<list>` and their consumers (apps, bots, partners). Say whether any API contract, path or auth changes. |
| **Risk and impact** | `<Low, medium or high>`. State it as production. Note that manual APIM changes can be overwritten by the pipeline (found in earlier work), so confirm none are pending. |
| **Implementation plan** | 1. Confirm the release branch contains only the approved changes. 2. Get pipeline approval. 3. Deploy in order `<Dev, SIT, UAT, Prod>`. 4. Verify each stage before the next. |
| **Test plan** | Call the changed operations through APIM after each stage, check status codes, and watch gateway logs and capacity for errors after the prod deploy. |
| **Backout plan** | Redeploy the previous release tag, or revert the commit on the release branch and rerun the pipeline. For policy changes, restore the previous policy version. |
| **Planned window** | 16 Nov, `<time and timezone>`. Include whether a freeze applies. |
| **Approvers** | The change manager, the APIM owner, your team lead, and the release pipeline approvers. Add the app owners for changed APIs. |
