Hi, thanks for flagging this. To answer your question: main has no named-values support, so a deployment from main does not create or manage any named value. A search of main finds no APIM/named-values folder, no named-value Terraform and no API template defining one. The three values you see in the prod CUS Portal are therefore not created by main's deployment.

Your Portal screenshot is filtered by "vendor", so it shows only the three vendor-okta-jwt-* values. PR 60878 (DVA / IVA scopes named values and policy update) is on develop but not on main, and so are the named-value Terraform and the namedValueConfig.yaml files.

One more thing to know before the release: your develop version of virtual_assistant_api_inbound_policy.xml also uses IVR-SCOPES, DVA-SCOPES, VENDOR-OKTA-JWT-B2C-OPENID-AUTHORIZATION-URL, VENDOR-OKTA-JWT-B2C-AUDIENCE and VENDOR-OKTA-JWT-B2C-ISSUER.
