
*(No CLI command — this is done in APIM portal, Test tab)*

## 3. Show the AKS pod logs capturing the real 401 + stack trace
```powershell
kubectl logs api-cims-56fbf694d6-5gfq9 -n api-cims-v1 -c api-cims --since-time="2026-07-23T15:29:00Z" | Select-String -Pattern "20258796","kanasmc","Exception" -Context 5,5
```

## 4. Show the credential is empty in the pod's environment
```powershell
kubectl exec -it api-cims-56fbf694d6-5gfq9 -n api-cims-v1 -c api-cims -- sh -c 'echo "KANA:$KANA_API_AUTHORIZATION_KEY:END"'
```


## 6. Show the same value IS present in the Kubernetes Secret object
```powershell
kubectl get secret kvadscusprdihub01-secrets-syncd -n api-cims-v1 -o jsonpath='{.data.KANA_API_AUTHORIZATION_KEY}' | Measure-Object -Character
```

## 7. Show other secrets in the SAME pod work fine (rules out a broad sync issue)
