**Title:**
```
Add DEV ACR to POC allowed registries for backup restore validation
```

**Description:**

## Summary

Added DEV ACR (`acrbfhaksihubeus2dev02.azurecr.io`) to the POC allowed registries list to support AKS backup and restore validation on `aks-bfhaks-ihub-eus2-poc-02`.

## Why

As part of the AKS backup and restore validation initiative, DEV workloads are being restored to the POC-02 cluster. The restored workloads use container images from the DEV ACR (`acrbfhaksihubeus2dev02.azurecr.io`). The POC Azure Policy only allows images from `acrbfhaksihubeus2poc01.azurecr.io` by default, causing the Gatekeeper admission webhook to deny pod creation with:

```
admission webhook "validation.gatekeeper.sh" denied the request:
Container image acrbfhaksihubeus2dev02.azurecr.io/customer-lookup-api:harness-1508
has not been allowed
```

## Changes

### `bfhaksplatform_instances/ihub-poc-eus2/conf.yaml`
- Added `acrbfhaksihubeus2dev02.azurecr.io` to `allowed_registries` under `azure_policy`

## Notes
- This is a temporary change for restore validation purposes only
- Will be reverted once restore validation is complete
- No impact on existing POC-01 workloads
