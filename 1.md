**TITLE**

[PERF] ASM Istio Upgrade v1.28→v1.29 Failed Cluster Recovery & Version Mismatch


**DESCRIPTION**

**INCIDENT SUMMARY**

Istio ASM upgrade from v1.28 → v1.29 on aks-bfhaks-ihub-cus-perf-01 failed during nodepool reconciliation, leaving cluster and nodepools in Failed state.

---

**ROOT CAUSE**

1. Kubernetes version mismatch on userpool2:
   - Cluster control plane: v1.35.6
   - userpool2 nodes: v1.35.6 & v1.36.3 (mixed)
   
2. 9 PodDisruptionBudgets with minAvailable=1 and zero allowed disruptions blocked pod eviction during node drain, preventing graceful upgrade

---

**IMPACT**

- ASM upgrade failed mid-cycle
- Cluster & nodepools entered Failed provisioning state
- No live outage (traffic already shifted to App Service)
- ~1.5 hour recovery window

---

**RESOLUTION EXECUTED**

1. Identified version mismatch via `kubectl get nodes`
2. Backed up all cluster PDBs as safety measure
3. Deleted 9 blocking PDBs to unblock pod eviction:
   - api-acquisitionvendor-pdb
   - api-brandcodes-pdb
   - api-consumersearch-pdb
   - api-creditbureaservice-pdb
   - fraud-pdb
   - api-newacctccadata-pdb
   - api-ofac-pdb
   - api-snapparmservice-pdb
   - catools-api-pdb

4. Created Azure DevOps release pipeline for cluster reconciliation
5. Reconciled userpool2 (18 nodes) → Succeeded
6. Reconciled systempool → Succeeded
7. Reconciled cluster → Succeeded
8. Restored all PDBs post-reconciliation
9. Retried Istio upgrade v1.28 → v1.29 → Succeeded
