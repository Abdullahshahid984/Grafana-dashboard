In AKS, a pod (api-cims) uses envFrom to bulk-import all keys from a Kubernetes Secret (synced via CSI driver from Azure Key Vault) into its container's environment variables. One specific key, KANA_API_AUTHORIZATION_KEY, is confirmed present with real content at every upstream layer — the Key Vault secret itself (proven, since another Azure App Service uses the same secret successfully), the CSI-mounted file in the pod (40 chars), and the Kubernetes Secret object (56 base64 chars, decodable). But this same key shows up empty (0 chars) when read as an environment variable inside the running pod — while every other key in that same Secret object populates correctly. This env var is confirmed to be what builds the Authorization header for calls to kanasmc.alldata.net, so its being empty directly explains the 401 Unauthorized seen on that call.

Why would one specific key in an envFrom-populated Secret fail to appear as an environment variable while all others populate correctly, when the file and Secret object both confirm the data is present? Is this most likely a stale pod snapshot (env vars set once at startup, before this key synced) fixable by restart, or something more structural?
