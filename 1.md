**Ticket 1:**

**Title:** Add KEDA for POC-02 cluster to support backup restore validation


**Description:**
As part of the AKS backup and restore validation initiative, POC-02 (`aks-bfhaks-ihub-eus2-poc-02`) is being used as the restore target cluster. When DEV workloads are restored to POC-02, the restored workloads include ScaledObject resources that depend on KEDA for autoscaling. Without KEDA installed on POC-02, pods fail to scale and events show FailedGetExternalMetric errors.

**Acceptance Criteria:**
- KEDA added to POC conf.yaml for poc-02 cluster
- PR raised, reviewed and merged
- POC bfhaksplatform pipeline run successfully
- KEDA operator running on poc-02 confirmed via kubectl

**Ticket 2:**

**Title:** Add DEV ACR to POC allowed registries for backup restore validation

**Type:** Task

**Description:**
As part of the AKS backup and restore validation initiative, DEV workloads are being restored to POC-02 cluster. The restored workloads use container images from the DEV ACR (`acrbfhaksihubeus2dev02.azurecr.io`). The POC Azure Policy only allows images from the POC ACR by default, causing the Gatekeeper admission webhook to deny pod creation. DEV ACR needs to be added to the POC allowed registries list to unblock restore validation.


**Note:** This is a temporary change. DEV ACR should be removed from POC allowed registries once restore validation is complete.
