> Hi all, an update on the APIM and Traceable investigation (item 1).
>
> **What I've found so far (from the vendor and Microsoft docs):**
>
> - The Traceable policy in APIM sends each request to the Traceable agent VM and, in the standard (synchronous) version, [waits for its reply before sending the call to the backend](https://developer.harness.io/web-application-and-api-protection-waap-protection-protection/data-collection/gateways-load-balancers/azure/azure-apim#:~:text=waits%20for%20a%20response%20from%20ext_cap%20before%20it%20forwards%20the%20request%20to%20the%20backend).
> - APIM finds the agent through a [named value (`traceable-endpoint`)](https://developer.harness.io/web-application-and-api-protection-waap-protection-protection/data-collection/gateways-load-balancers/azure/azure-apim#:~:text=Create%20a%20named%20variable%20traceable-endpoint) on [port 5442](https://developer.harness.io/web-application-and-api-protection-waap-protection-protection/installation/optional-installation-topics/agent-ports#:~:text=Traceable%20Module%20Extension) (HTTP) or [port 5443](https://developer.harness.io/web-application-and-api-protection-waap-protection-protection/installation/optional-installation-topics/agent-ports#:~:text=TLS%20Server) (TLS), and the agent has a [`/health` check](https://developer.harness.io/web-application-and-api-protection-waap-protection-protection/installation/optional-installation-topics/platform-agent-health-check#:~:text=HTTP%20Health%20Check) I can use for the connection test.
> - APIM's [default timeout for that call is 60 seconds](https://learn.microsoft.com/azure/api-management/send-request-policy#attributes), and [errors are not ignored by default](https://learn.microsoft.com/azure/api-management/send-request-policy#:~:text=the%20error%20will%20be%20ignored). So if the agent can't be reached, each request could wait up to 60 seconds. That is very long for a call made on every request. Microsoft's own [example uses a 20-second timeout](https://learn.microsoft.com/azure/api-management/send-request-policy#example).
> - The vendor's release notes show policy and blocking changes in the last year ([policy safeguards added](https://developer.harness.io/release-notes/runtime-protection-agent/waap-release-notes/2026/agent-release-notes/traceable-platform-agent#:~:text=Improved%20safeguards%20have%20been%20added%20to%20the%20Azure%20APIM%20policy), [new blocking endpoint for Azure APIM](https://developer.harness.io/release-notes/runtime-protection-agent/waap-release-notes/2026/agent-release-notes/traceable-platform-agent#:~:text=Azure%20APIM%20now%20uses%20the%20new%20blocking%20evaluation%20endpoint), [blocking on by default](https://developer.harness.io/release-notes/runtime-protection-agent/waap-release-notes/2026/agent-release-notes/traceable-platform-agent#:~:text=Blocking%20is%20now%20enabled%20by%20default%20for%20all%20deployments)), so a version mismatch between the policy and the agent is possible.
> - For capacity: [slow calls raise APIM's Capacity metric](https://learn.microsoft.com/azure/api-management/api-management-capacity#capacity-metric-behavior), and a [full instance gets slow and times out instead of throttling](https://learn.microsoft.com/azure/api-management/api-management-capacity#:~:text=increased%20latency%2C%20dropped%20connections%2C%20and%20time-out%20errors).
