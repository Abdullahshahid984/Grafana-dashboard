**Short Description:**
AKS rolling restart needed to fix stale Key Vault secret (KANA_API_AUTHORIZATION_KEY) causing 401 on CIMS Process API

**Description:**
Testing of AKS PRD-CUS unused Kana integration reproduced a 401 Unauthorized on the CIMS Process API. `KANA_API_AUTHORIZATION_KEY` is correctly stored in Key Vault and synced to the pod, but reads as empty at the application/env-var level isolated to this one credential in this one pod (all other secrets, including in a separate app using the same Key Vault, populate fine). K8s env vars are set only at pod startup and don't auto-refresh; this pod hasn't restarted since 7/22, so it likely holds a stale snapshot. A rolling restart should force it to re-read the current, correct secret.
