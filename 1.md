Hi Team,

I'm currently seeing a failure in the AKS platform upgrade pipeline when Terraform attempts to manage our Azure Managed Grafana v12 workspace.

**Issue**

The current AzureRM Terraform provider version **4.47.0** does not support Grafana v12. The pipeline is failing with the following error:

```text
Error: expected grafana_major_version to be one of ["10" "11"], got 12
```

Our production workspace is already running **Grafana v12**, so the current provider version is preventing Terraform from properly managing or importing the workspace.

**Root Cause**

I verified the AzureRM provider compatibility:

* **AzureRM 4.47.0** Grafana v12 is not supported
* **AzureRM 4.62.0** Grafana v12 support was introduced
* **AzureRM 5.0.0** Grafana v13 support was added

HashiCorp's AzureRM v4.62.0 changelog confirms that `azurerm_dashboard_grafana` added support for Grafana 12.

**Microsoft Grafana 12 Upgrade Status**

According to Microsoft's Azure Managed Grafana documentation, Grafana 11 support was retired on **June 15, 2026**. Workspaces still running Grafana 11 after that date were automatically upgraded to Grafana 12.

Microsoft also notes that Grafana 12 includes significant breaking changes and that the upgrade from Grafana 11 to Grafana 12 is irreversible. Our workspace is already on Grafana 12, so the current issue is specifically the Terraform provider compatibility with the existing workspace.

**Troubleshooting Performed**

I attempted the following:

* Terraform import
* Configuration-level changes/overrides
* Provider/cache refresh

These did not resolve the issue because the Grafana version validation is enforced by the AzureRM provider schema itself.

The blocker consistently remains that **AzureRM 4.47.0 does not recognize Grafana 12 as a supported Grafana version**.

I see two possible options:

**Option 1 Minimum required change**

Upgrade AzureRM from **4.47.0 to 4.62.0 or later within the 4.x release line**.

This is the minimum provider version that introduces Grafana 12 support and would keep us within the existing AzureRM 4.x major version.

**Option 2 Move to AzureRM 5.x**

Upgrade to AzureRM 5.x as part of a broader provider upgrade.

AzureRM 5.0.0 adds support for Grafana 13, but it is a **major provider release** and includes behavioral changes and removed/deprecated resources or fields. Therefore, this option would require broader regression testing across our existing Terraform-managed Azure resources.


Could you please share your thoughts on the following:

1. Should we proceed with the minimum required upgrade to **AzureRM 4.62.0+**?
2. Or should we use this opportunity to move to **AzureRM 5.x**?
3. Are there any known dependencies or risks with upgrading the AzureRM provider in our existing Terraform modules?
4. If approved, can we first validate the selected approach in DEV, review the Terraform plan for unexpected changes, and then promote it through the remaining environments?

Once we agree on the approach, I can proceed with the DEV validation and share the results before any staging or production rollout.
