Hey team, wanted to give a quick update on the AKS backup/restore situation since I know there's some confusion about what actually caused what.

So when I set up the dev-rst cluster (the restore/validation cluster from Azure Backup), it started causing an RBAC issue on the original dev cluster. Role assignments and federated credentials were getting messed up because the pipeline was treating the restore cluster like it needed its own full run, and it ended up fighting with the original cluster over the same Terraform state. Basically every time it ran, it would touch the original cluster's stuff too. I dug into it, found the root cause, and fixed it the same day. Now the original cluster runs completely untouched like before, and the restore cluster just gets the one extra credential it actually needs to authenticate its restored pods, nothing else gets recreated or touched. I also fixed the alert naming so the two clusters don't clash on alert names either. This part was genuinely caused by the backup/restore setup, and it's sorted now.

After that, I was working with the applications team and ran into a few more issues that people are assuming are also because of AKS backup, but they're actually unrelated. First one was apps using the wrong SQL DB in every environment, so I corrected them to point to the right DB. Then some pods weren't coming up in a few namespaces, turned out the SIT configmap had wrong values, I told the dev, he updated it and it started working. Then yesterday the same environment had another issue, this time a wrong port being used, I told him to fix it and it worked right after.

One more thing - Sahil flagged an incident about the Wiz Broker disconnecting on the dev-rst cluster. I checked it out and the pod is running fine and Wiz is connected, so there's no actual issue there. Flagging it just so you're aware it came up, but it looks like it was just a transient blip on the test cluster, nothing that needed a fix.

So to be clear, only the RBAC issue was actually caused by the backup setup, and that's fixed. The SQL DB, configmap, and port issues were separate app-level problems that surfaced around the same time. And the Wiz Broker alert turned out to be a non-issue on closer look. None of it points back to AKS backup itself beyond the one RBAC fix.
