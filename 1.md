
**1. Which branch you are on.** `main` is production in this repo, and a stale checkout could miss it.

```powershell
git branch --show-current
git fetch origin
```

**2. Search both branches, not just the current checkout.**

```powershell
git grep -n "x-twoway-ssl" origin/main
git grep -n "x-twoway-ssl" origin/develop
```

**3. Search for the diagnostic resource itself, in case the header list is built differently.**

```powershell
git grep -n -i "api_management_diagnostic" origin/main
git grep -n -i "applicationinsights" origin/main -- "*.tf" "*.json" "*.tfvars"
```

How to read the results:
- **All empty:** the diagnostic isn't in this repo, so it was set up by hand in the Portal or lives in another repo, for example a platform or infra one. A Portal change then isn't reverted by the next release here.
- **Matches on `develop` only:** the diagnostic is code-managed for non-prod only. Change it there for SIT or UAT, and Prod stays manual.
- **Matches on `main`:** it is code-managed, so make the change in code through a PR.

In every case, ask your team whether anyone knows who set up the global diagnostic, so a manual change isn't later overwritten by someone's pipeline. Send me what the commands return.
