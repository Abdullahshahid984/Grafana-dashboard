This is a PowerShell quoting problem, not a problem with the command. PowerShell strips the inner double quotes when it passes the JSON to `kubectl`, so `kubectl` gets `{spec:{...}}` and rejects it. Nothing was changed.

The most reliable fix is to put the patch in a file:

```powershell
Set-Content -Path patch.json -Value '{"spec":{"minReplicaCount":6,"maxReplicaCount":6}}'
```

```powershell
kubectl patch scaledobject apiprofile-prometheus-scaler -n api-profile-v1 --type merge --patch-file patch.json
```

If your `kubectl` is too old for `--patch-file`, escape the quotes inline instead:

```powershell
kubectl patch scaledobject apiprofile-prometheus-scaler -n api-profile-v1 --type merge -p '{\"spec\":{\"minReplicaCount\":6,\"maxReplicaCount\":6}}'
```

Then check:

```powershell
kubectl get hpa -n api-profile-v1
kubectl get pods -n api-profile-v1
```

The error came back before `kubectl` looked for the ScaledObject, so I still haven't confirmed the name `apiprofile-prometheus-scaler`. If the patch says `NotFound`, run `kubectl get scaledobject -n api-profile-v1` and use the name it shows.

Also save the current settings first, if you haven't:

```powershell
kubectl get scaledobject apiprofile-prometheus-scaler -n api-profile-v1 -o yaml > scaledobject-backup.yaml
```
