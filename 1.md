Yes, that flow is exactly right. All 4 steps are aligned. Here is why each step matters:

**Step 1: Configure new cluster in parallel**
- Faster than sequential gets POC2 infrastructure ready while DEV is running

**Step 2: Run pipeline to create new cluster**
- Provisions POC2 AKS cluster, identities, etc.

**Step 3: Run workload onboarding** ← **This is the critical step**
- Creates Managed Identities for workloads on POC2
- **Creates federated credentials on DEV MIs that point to POC2's OIDC issuer**
- Without this step, restored pods will get 401 Unauthorized (AADSTS700211)

**Step 4: Restore previous cluster backup to new cluster**
- Restore DEV backup to POC2
- Pods authenticate successfully because federated credentials from step 3 are in place

The key insight: **Step 3 enables step 4 to work.** If you skip step 3 or run it after restore, pods will fail to authenticate.

Our solution automates step 3 for restore scenarios it detects environment `dev` and automatically creates the right federated credentials pointing to POC2's OIDC issuer.
