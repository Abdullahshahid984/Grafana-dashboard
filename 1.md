Yes, setting path to "" should work for all three endpoints. With an empty suffix, the consumer URL is the APIM host plus the operation path, so:

- <apim-host>/saat-auth/oauth2/token -> https://sandbox.api.ethocaweb.com/saat-auth/oauth2/token
- <apim-host>/ethoca/consumer-clarity/searches -> https://sandbox.api.ethocaweb.com/ethoca/consumer-clarity/searches
- <apim-host>/ethoca/consumer-clarity/backoffice-searches -> https://sandbox.api.ethocaweb.com/ethoca/consumer-clarity/backoffice-searches

That also avoids the doubled /ethoca.

One thing to check: I believe only one API per APIM instance can have an empty suffix, so please make sure no other API on the External APIM uses an empty suffix or overlaps /saat-auth or /ethoca. It may be worth trying SIT first.
